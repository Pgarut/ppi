# Software Requirements Specification (SRS)
## Sistem Informasi Madrasah Tingkat MA dan MTs

Dokumen ini adalah turunan teknis dari `PRD.md` dan menjadi acuan detail bagi implementasi (termasuk saat dikerjakan dengan bantuan CLI AI coding) agar hasilnya konsisten antar sesi pengerjaan.

---

## 1. Pendahuluan

### 1.1 Tujuan Dokumen
Mendefinisikan kebutuhan fungsional dan non-fungsional secara rinci per role, sebagai acuan pengembangan `frontend/` (Flutter) dan `backend/` (Cloudflare Workers + D1).

### 1.2 Referensi
- `PRD.md`
- `docs/menu_sistem.md`
- `docs/erd.md` / `schema.sql`

### 1.3 Aktor Sistem
Admin, Kepala Madrasah, Wakil Kurikulum, Guru Mapel/Wali Kelas, Guru BK. **Siswa bukan aktor sistem.**

---

## 2. Deskripsi Umum Sistem

### 2.1 Arsitektur
- **Frontend**: Flutter (web untuk Admin; web + mobile responsif untuk role lain), multi-login split screen, Mini Sidebar Dashboard (Admin), Academic Management Dashboard dengan Mini Sidebar + Topbar (role lain).
- **Backend**: Cloudflare Workers sebagai API, dipisah per route/role (`backend/src/routes/<role>/`), dengan `middleware/role_guard.ts` untuk pembatasan akses.
- **Database**: Cloudflare D1 (SQLite), skema pada `schema.sql`.
- **Deploy**: GitHub → Cloudflare Pages/Workers, paket free tahap awal.

### 2.2 Batasan Umum
- Tidak ada modul atau endpoint yang diekspos ke aktor siswa.
- Modul Kesiswaan dan Musyrif/Musyrifah tidak termasuk dalam versi ini.

## 3. Kebutuhan Fungsional (Functional Requirements)

### 3.1 Admin
| ID | Kebutuhan |
|---|---|
| FR-A01 | Sistem menyediakan dashboard ringkasan statistik guru, siswa, kelas, absensi, nilai, jadwal |
| FR-A02 | Admin dapat mengelola master data: tahun ajaran, semester, jurusan, tingkat, kelas, mapel, guru, siswa, ruangan |
| FR-A03 | Admin dapat memonitor dan merekap absensi guru & siswa seluruh sekolah |
| FR-A04 | Admin dapat memvalidasi nilai dan memonitor status rapor |
| FR-A05 | Admin dapat mencetak dan mengarsipkan rapor |
| FR-A06 | Admin dapat mengelola akun pengguna dan hak akses tiap role |
| FR-A07 | Admin dapat melakukan backup dan restore database |
| FR-A08 | Sistem mencatat seluruh aktivitas pengguna pada log aktivitas |

### 3.2 Kepala Madrasah (View Only)
| ID | Kebutuhan |
|---|---|
| FR-K01 | Sistem menampilkan dashboard ringkasan akademik dan statistik sekolah |
| FR-K02 | Kepala Madrasah dapat melihat jadwal pelajaran dan jadwal guru |
| FR-K03 | Kepala Madrasah dapat melihat statistik dan rekap absensi, nilai, rapor |
| FR-K04 | Kepala Madrasah dapat melihat statistik konseling dan bakat minat dari BK |
| FR-K05 | Kepala Madrasah dapat mengakses laporan lintas modul (read only, tanpa aksi ubah data) |

### 3.3 Wakil Kurikulum
| ID | Kebutuhan |
|---|---|
| FR-W01 | Wakil Kurikulum dapat membuat, mengedit, dan memvalidasi jadwal pelajaran |
| FR-W02 | Sistem menghitung dan menampilkan beban mengajar & distribusi guru |
| FR-W03 | Wakil Kurikulum dapat mengatur bobot nilai (harian/tugas/UTS/UAS) |
| FR-W04 | Wakil Kurikulum dapat memonitor status pengumpulan nilai per guru |
| FR-W05 | Wakil Kurikulum dapat memproses kenaikan kelas dan mencetak surat keputusan |
| FR-W06 | Wakil Kurikulum dapat mengelola data alumni |

### 3.4 Guru Mapel / Wali Kelas
| ID | Kebutuhan |
|---|---|
| FR-G01 | Guru dapat melihat jadwal mengajar dan jadwal kelas |

| FR-G04 | Wali kelas dapat menginput nilai rapor dan catatan wali kelas |
| FR-G05 | Guru dapat mengajukan pengaduan (perilaku/kasus) dengan lampiran bukti foto/video |
| FR-G06 | Wali kelas dapat melihat rekap absensi dan nilai kelas yang diampu |

### 3.5 Guru BK
| ID | Kebutuhan |
|---|---|
| FR-B01 | Guru BK dapat melihat grafik nilai dan perkembangan akademik siswa |
| FR-B02 | Guru BK dapat mencatat dan menjadwalkan sesi konseling (individu/kelompok) |
| FR-B03 | Guru BK dapat mencatat data bakat, minat, dan pengembangan siswa |
| FR-B04 | Guru BK dapat melihat laporan pengaduan yang dilaporkan Guru Mapel/Wali Kelas |
| FR-B05 | Guru BK dapat menghasilkan laporan konseling, bakat, minat, dan monitoring akademik |

---

## 4. Kebutuhan Non-Fungsional (NFR)

| ID | Kategori | Kebutuhan |
|---|---|---|
| NFR-01 | Performa | Waktu muat dashboard < 2 detik pada koneksi standar |
| NFR-02 | Keamanan | Autentikasi wajib, otorisasi berbasis role di setiap endpoint backend |
| NFR-03 | Auditability | Setiap aksi tulis (create/update/delete) tercatat di `log_aktivitas` |
| NFR-04 | Ketersediaan | Sistem tersedia selama jam operasional madrasah |
| NFR-05 | Skalabilitas | Struktur tabel mendukung tahun ajaran/semester baru tanpa migrasi ulang |
| NFR-06 | Kompatibilitas | Web modern dan mobile (Android/iOS) via Flutter responsif |
| NFR-07 | Konsistensi Data | Insert master data mengikuti urutan dependensi FK (lihat `schema.sql`) |

---

## 5. Kebutuhan Data
Struktur data lengkap ada di `schema.sql` dan `docs/erd.md`. Ringkasan kelompok tabel:
- Pengguna & hak akses
- Master data akademik
- Penjadwalan
- Absensi
- Nilai & rapor
- Pengaduan
- BK (konseling, bakat minat)
- Kenaikan kelas & alumni

---

## 6. Kebutuhan Antarmuka
- **Login**: multi-login dengan split screen (satu layar, pilihan role tervalidasi dari `users.role`).
- **Admin**: Mini Sidebar Dashboard, web only.
- **Role lain**: Academic Management Dashboard — Mini Sidebar + Topbar + Responsive Layout, web & mobile.
- Ikon-ikon modern (disarankan Tabler icon set atau setara) untuk seluruh role selain Admin.

## 8. Batasan Implementasi
- Tidak boleh ada endpoint atau layar yang bisa diakses tanpa role valid.
- Tidak ada entitas atau endpoint untuk login siswa di rilis ini.
- Semua tabel mengacu ke `tahun_ajaran_id`/`semester_id` aktif agar data tidak bercampur antar periode.
