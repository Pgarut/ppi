# Product Requirements Document (PRD)
## Sistem Informasi Madrasah Tingkat MA dan MTs

---

## 1. Latar Belakang
Madrasah (tingkat MA dan MTs) saat ini belum memiliki sistem informasi terpadu untuk mengelola data akademik (jadwal, absensi, nilai, rapor) dan layanan bimbingan konseling. Proses masih manual/tersebar, sehingga monitoring oleh Kepala Madrasah dan koordinasi antar Wakil Kurikulum, Guru Mapel/Wali Kelas, dan Guru BK menjadi lambat.

## 2. Tujuan
- Menyediakan satu sistem terpusat untuk seluruh proses akademik non-siswa.
- Mempercepat proses input dan monitoring absensi, nilai, dan rapor.
- Memberi visibilitas real-time kepada Kepala Madrasah tanpa perlu akses manual ke tiap guru.
- Mendukung tugas Guru BK (konseling, bakat minat) dalam satu platform yang sama.

## 3. Ruang Lingkup

### 3.1 Termasuk
- Modul akademik: master data, penjadwalan, absensi, nilai, rapor.
- Modul manajemen pengguna dan hak akses (Admin).
- Modul BK: konseling, bakat minat, monitoring akademik siswa.
- Modul pengaduan (perilaku/kasus) dari Guru Mapel/Wali Kelas ke Guru BK.
- Modul kenaikan kelas dan data alumni.
- Aplikasi berbasis web (Admin) dan web + mobile responsif (role lainnya).

### 3.2 Tidak Termasuk (Out of Scope)
- **Tidak ada akses untuk siswa** — siswa bukan pengguna sistem pada versi ini.
- Modul Kesiswaan dan Musyrif/Musyrifah (dihapus dari rencana awal).
- Pembayaran/SPP, perpustakaan, dan modul non-akademik lain.

## 4. Target Pengguna (5 Role)

| Role | Peran Utama | Akses |
|---|---|---|
| Admin | Mengelola seluruh master data, pengguna, dan sistem | Penuh, berbasis web |
| Kepala Madrasah | Memantau kondisi sekolah secara ringkas | View only, web & mobile |
| Wakil Kurikulum | Mengatur jadwal, validasi nilai, kenaikan kelas | Operasional, web & mobile |
| Guru Mapel/Wali Kelas | Mengajar, input nilai/absensi, wali kelas | Operasional, web & mobile |
| Guru BK | Konseling, bakat minat, monitoring siswa bermasalah | Operasional, web & mobile |

## 5. Fitur Utama per Role
Rincian menu lengkap ada di `docs/menu_sistem.md`. Ringkasan:

- **Admin**: dashboard sistem, master data, monitoring absensi/nilai, validasi nilai, rapor, pengaturan (user, hak akses, backup, log).
- **Kepala Madrasah**: dashboard ringkasan, jadwal, statistik absensi/nilai, laporan lintas modul (view only).
- **Wakil Kurikulum**: penjadwalan, validasi nilai, laporan, kenaikan kelas, data alumni.
- **Guru Mapel/Wali Kelas**: input absensi & nilai, pengaduan siswa, data wali kelas.
- **Guru BK**: konseling, bakat minat, lihat pengaduan, laporan BK.

## 6. Kebutuhan Non-Fungsional
- **Performa**: dashboard utama termuat < 2 detik pada koneksi standar.
- **Keamanan**: autentikasi berbasis role, semua aksi tercatat di log aktivitas.
- **Ketersediaan**: sistem dapat diakses selama jam operasional sekolah tanpa downtime signifikan.
- **Skalabilitas**: struktur data mendukung penambahan tahun ajaran/semester tanpa migrasi besar.
- **Kompatibilitas**: web modern (desktop) dan mobile responsif (Android/iOS via Flutter).

## 7. Teknologi
- Frontend: Flutter/Dart (web + mobile)
- Backend: Cloudflare Workers
- Database: Cloudflare D1 (paket free tahap awal)
- Repository & CI/CD: GitHub

## 8. Asumsi & Batasan
- Tahap awal menggunakan paket Cloudflare D1 free tier — perlu diperhitungkan batas storage/request.
- Pengembangan awal dibantu CLI AI coding, sehingga dokumen PRD/SRS/ERD ini menjadi acuan tetap agar hasil generate konsisten antar sesi.
- Modul Kesiswaan dan Musyrif ditunda, dapat ditambahkan di fase berikutnya jika diperlukan.

## 9. Roadmap Tahap Awal
1. Penyusunan PRD, SRS, ERD (dokumen ini).
2. Struktur folder proyek (frontend & backend).
3. Implementasi skema database D1.
4. Modul Admin (master data, user & hak akses).
5. Modul akademik (jadwal, absensi, nilai, rapor) per role.
6. Modul BK & pengaduan.
7. Uji coba internal per role.

## 10. Kriteria Keberhasilan
- Seluruh 5 role dapat login dan mengakses menu sesuai hak aksesnya masing-masing.
- Data absensi dan nilai yang diinput Guru Mapel/Wali Kelas dapat langsung terlihat oleh Wakil Kurikulum dan Kepala Madrasah.
- Pengaduan yang diinput Guru Mapel/Wali Kelas dapat dilihat oleh Guru BK tanpa proses manual.
- Tidak ada jalur akses yang tersedia untuk siswa.
