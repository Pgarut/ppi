# Dokumen Keamanan Sistem
## Sistem Informasi Madrasah Tingkat MA dan MTs

---

## 1. Autentikasi

### 1.1 Metode
- Login menggunakan kombinasi `username` + `password_hash`
- Password disimpan dengan **bcrypt** (cost factor ≥ 10)
- Setelah login, sistem mengeluarkan **JWT (JSON Web Token)** yang berlaku selama 8 jam

### 1.2 JWT Payload
```json
{
  "sub": 1,
  "username": "admin",
  "role": "admin",
  "guru_id": null,
  "iat": 1680000000,
  "exp": 1680030000
}
```

### 1.3 Multi-Login
- Split screen login memvalidasi role dari tabel `users`
- Satu user hanya memiliki satu role (tidak multi-role)

### 1.4 Logout
- Token di-blacklist atau dihapus dari sisi klien
- Opsional: simpan token invalid ke redis/tabel blacklist

## 2. Otorisasi — Role-Based Access Control (RBAC)

### 2.1 Middleware Role Guard
Setiap request melewati middleware `role_guard.ts`:
```
Request → Auth Middleware (verifikasi JWT) → Role Guard (cek role) → Route Handler
```

### 2.2 Role yang Didukung
| Role | Level |
|------|-------|
| admin | 1 (tertinggi) |
| kepala_sekolah | 2 |
| wakil_kurikulum | 3 |
| guru_mapel_wali_kelas | 4 |
| guru_bk | 4 |

### 2.3 Tabel hak_akses_modul
Digunakan untuk validasi aksi per modul secara granular:
```sql
-- Setiap baris menentukan apakah suatu role bisa view/create/edit/delete/validate pada modul tertentu
SELECT 1 FROM hak_akses_modul
WHERE role = 'guru_mapel_wali_kelas'
  AND modul = 'absensi'
  AND aksi = 'create';
```
Jika tidak ada baris yang cocok, akses ditolak (403).

### 2.4 Enforce di Backend
- Backend **tidak boleh** mengandalkan frontend untuk pembatasan akses
- Setiap endpoint backend memverifikasi role user dari JWT
- Frontend hanya menyembunyikan tombol/menu — backend yang menjadi lapisan keamanan utama

## 3. Enkripsi & Proteksi Data

### 3.1 Password
- Tidak disimpan plaintext
- Dicompare menggunakan bcrypt (`password_verify()` / `bcrypt.compare()`)

### 3.2 Transport
- **HTTPS** wajib di semua lingkungan (production)
- Cloudflare Workers secara default sudah HTTPS

### 3.3 Database (Cloudflare D1)
- D1 tidak mendukung enkripsi-at-rest secara native, tapi data hanya bisa diakses melalui Worker API
- Tidak ada akses publik langsung ke database

### 3.4 Environment Variables
Semua konfigurasi sensitif disimpan di `wrangler.toml` atau secrets Cloudflare:
```
JWT_SECRET        — rahasia signing JWT (min 256-bit)
DB_NAME           — nama database D1
API_KEY_INTERNAL  — key untuk komunikasi internal Worker
```

## 4. Audit & Logging

### 4.1 Log Aktivitas
Semua aksi tulis (create, update, delete, validasi) dicatat di tabel `log_aktivitas`:

| Kolom | Contoh |
|-------|--------|
| user_id | 1 |
| aksi | 'input_nilai' |
| modul | 'nilai' |
| detail | 'Input nilai UTS Matematika untuk siswa_id=10' |
| ip_address | '192.168.1.1' |
| created_at | '2025-07-26 08:30:00' |

### 4.2 Log yang Dicatat
- Login & logout
- Create/update/delete master data
- Input & edit absensi
- Input & edit nilai
- Validasi jadwal, nilai, kenaikan kelas
- Backup & restore database
- Perubahan hak akses user

### 4.3 Log yang Tidak Perlu Dicatat
- Request GET/view (untuk menghindari spam log)

## 5. Proteksi Serangan Umum

### 5.1 SQL Injection
- Cloudflare D1 menggunakan parameterized queries (binding)
- **Tidak boleh** ada concatenation string untuk query SQL
- Contoh aman:
```typescript
db.prepare('SELECT * FROM users WHERE username = ?').bind(username).all();
```

### 5.2 XSS (Cross-Site Scripting)
- Flutter/Dart secara default sudah aman dari XSS (tidak render HTML mentah)
- Untuk input teks dari user: escape sebelum ditampilkan

### 5.3 CSRF
- Flutter web menggunakan token JWT di header `Authorization`
- Tidak ada session cookie-based yang rentan CSRF

### 5.4 Brute Force
- Limit login: maksimal **5 percobaan gagal** per username dalam 15 menit
- Setelah terkena limit, akun di-lock sementara (15 menit)
- Dicatat di `log_aktivitas`

### 5.5 Rate Limiting
- Opsional: terapkan rate limiting di Worker (via middleware atau Cloudflare WAF)
- Batas default: 100 request/menit per IP

## 6. Manajemen Sesi

| Aspek | Kebijakan |
|-------|-----------|
| Masa berlaku token | 8 jam |
| Refresh token | Opsional — jika diimplementasikan, berlaku 7 hari |
| Max session per user | 5 sesi bersamaan |
| Sesi tidak aktif | Auto logout setelah 30 menit (via frontend) |

## 7. Backup & Restore

### 7.1 Backup
- Dilakukan oleh Admin melalui endpoint `POST /api/admin/backup`
- Output: file SQL dump dari seluruh tabel D1
- Disimpan di Cloudflare R2 atau penyimpanan eksternal
- Backup dienkripsi sebelum disimpan (AES-256)

### 7.2 Restore
- Dilakukan oleh Admin melalui `POST /api/admin/restore`
- Hanya bisa dilakukan saat sistem tidak digunakan (luar jam operasional)
- Sebelum restore, sistem melakukan backup otomatis data saat ini terlebih dahulu

### 7.3 Jadwal Backup Otomatis (Rekomendasi)
- Harian (pukul 02:00) — full database
- Mingguan — archive ke penyimpanan eksternal
