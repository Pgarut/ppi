## Fase 2: Backend Master Data API (Estimasi: 1 minggu)

Prioritas tertinggi karena semua modul lain bergantung pada data master.

### 2.1 CRUD Tahun Ajaran & Semester
- [ ] `GET /api/admin/tahun-ajaran` — list
- [ ] `POST /api/admin/tahun-ajaran` — create
- [ ] `PUT /api/admin/tahun-ajaran/:id` — update
- [ ] `DELETE /api/admin/tahun-ajaran/:id` — delete
- [ ] `GET /api/admin/semester` — list by tahun_ajaran_id
- [ ] `POST /api/admin/semester` — create
- [ ] Log aktivitas untuk setiap aksi tulis

### 2.2 CRUD Master Data Lain
- [ ] Jurusan, Tingkat, Kelas
- [ ] Mata Pelajaran, Guru, Siswa
- [ ] Ruangan
- [ ] Validasi: unique constraint, FK dependency order (lihat schema.sql)

### 2.3 CRUD User & Hak Akses
- [ ] `GET/POST/PUT/DELETE /api/admin/users`
- [ ] `GET/POST /api/admin/hak-akses`
- [ ] Password hashing dengan bcrypt saat create user

### 2.4 Backup, Restore & Log
- [ ] `POST /api/admin/backup`
- [ ] `POST /api/admin/restore`
- [ ] `GET /api/admin/log-aktivitas` — pagination, filter

**Teknis:**
- Semua query menggunakan parameterized binding (D1)
- Setiap response mengikuti format `{ success, data, error }`
- Pagination: `?page=1&per_page=20`
- Filter: `?search=&status=&tahun_ajaran_id=`

## Catatan

- **Dependency kunci:** Fase 2 harus selesai sebelum Fase 3-7 bisa di-test dengan data nyata.
- **Paralel yg mungkin:** Fase 4 & 5 bisa dikerjakan paralel (beda role, beda endpoint).
- **Resiko:** Cloudflare D1 free tier — 100k read/day bisa cepat habis jika banyak polling. Solusi: cache di frontend, kurangi auto-refresh.
- **Prioritas user:** Jika salah satu role lebih urgent, bisa dikerjakan lebih awal dari urutan di atas.
